# Каталог: требования к Documents API

**Дата:** 2026-11-10
**Статус:** Черновик для команды бэкенда
**Связанные планы:** [2026-11-10-catalog-document-page.md](2026-11-10-catalog-document-page.md), [2026-11-10-catalog-redesign.md](2026-11-10-catalog-redesign.md)
**Макет:** https://claude.ai/artifact/CTizYaQ2RP7PuSBX71KkSp

Фронтенд каталога (Next.js, SSR/ISR, `revalidate = 300`, теги кеша `catalog` и `catalog:doc:{id}`) сейчас использует три эндпоинта:

| Метод | Путь | Использование |
|---|---|---|
| GET | `/catalog/documents?limit&cursor&category&tags&language&sort` | списки каталога → `{ documents: DocumentSummary[], nextCursor }` |
| GET | `/catalog/documents/{id}/meta` | страница документа → `CatalogDocumentMeta` |
| POST | `/catalog/documents/{id}/views` | учёт просмотра (из браузера) |

Ниже — что нужно добавить, чтобы включить функции из макета, которые сейчас отложены. Порядок — по приоритету.

## API-1 (P0). Миниатюры всех листов документа

> Задача для API. Её результат разблокирует ленту листов и полноэкранный просмотр с перелистыванием на странице документа.

**Контекст.** Сейчас у документа одна миниатюра (`thumbnailS3Key`) — первый лист. На странице документа есть лента листов, но для 2-го и следующих листов показываются только номера-заглушки.

**Что нужно.**

1. Генерировать превью **каждого листа** публичного документа:
   - при публикации (`visibility → public`) и при каждом сохранении публичного документа;
   - формат WebP, длинная сторона **1600 px** (основное превью и полноэкранный просмотр) и **240 px** (лента миниатюр);
   - фон белый, без обрезки, пропорции листа сохраняются (A4 210×297 / 297×210).
2. Класть файлы в тот же CDN-бакет, что и `thumbnailS3Key`, по предсказуемому ключу, например `catalog/{documentId}/{revision}/page-{index}-{size}.webp` (`revision` — чтобы обойти кеш CDN после изменения документа).
3. Отдавать в `GET /catalog/documents/{id}/meta` новое поле (старое `thumbnailS3Key` сохранить без изменений — обратная совместимость):

```json
"pageThumbnails": [
  { "index": 1, "s3Key": "catalog/…/page-1-1600.webp", "smallS3Key": "catalog/…/page-1-240.webp", "width": 1600, "height": 1131 },
  { "index": 2, "s3Key": "…", "smallS3Key": "…", "width": 1600, "height": 1131 }
]
```

   - `index` — с 1, массив отсортирован, длина = `metadata.pageCount`;
   - `width`/`height` — реальные размеры файла `s3Key` (нужны фронтенду, чтобы не было сдвига вёрстки);
   - если превью ещё генерируются — поле `null` (не пустой массив); фронтенд в этом случае показывает текущее поведение.
4. В списке (`GET /catalog/documents`) поле **не нужно** — экономим ответ.
5. Бэкфилл: сгенерировать превью для всех уже опубликованных документов (скрипт/джоба, идемпотентно).
6. После генерации — сбрасывать кеш страницы документа на фронтенде (вызов revalidate по тегу `catalog:doc:{id}`, если такой механизм есть; иначе фронтенд догонит за 300 с).

**Критерии приёмки.**
- Для документа из N листов `meta.pageThumbnails.length === N`, все `s3Key` и `smallS3Key` открываются с CDN (HTTP 200, `image/webp`).
- После изменения публичного документа в течение ≤ 5 мин `meta` отдаёт новые ключи (новая `revision`).
- Документ, снятый с публикации, — превью перестают отдаваться (или удаляются).
- Время ответа `meta` не выросло больше чем на 20 мс (p95).

**Фронтенд после релиза:** тип `CatalogDocumentMeta.pageThumbnails`, хелпер `buildPageStrip` (уже заложен в плане страницы документа) начинает возвращать картинки для всех листов; лента становится кликабельной, в полноэкранном просмотре появляются стрелки ‹ ›.

## API-2 (P1). Лайки

**Что нужно.**
- `POST /catalog/documents/{id}/likes` и `DELETE /catalog/documents/{id}/likes` — только для авторизованных (cookie сессии / JWT, как у остальных защищённых эндпоинтов); ответ `{ likesCount: number, likedByMe: boolean }`.
- Идемпотентность: повторный `POST` не увеличивает счётчик.
- `GET /catalog/documents/{id}/likes/me` → `{ likedByMe: boolean }` — отдельно от `meta`, чтобы `meta` оставалась кешируемой и одинаковой для всех.
- Rate limit на пользователя (например, 30 запросов/мин).
- CORS для домена сайта, если запрос идёт из браузера напрямую.

**Критерии приёмки.** `likesCount` в списке и `meta` отражает лайки с задержкой не более TTL кеша; гость получает 401.

**Фронтенд после релиза:** кнопка «♥ Нравится» в правой колонке и в мобильной панели; гость → модалка регистрации (как у «Открыть в редакторе»).

## API-3 (P1). Учёт просмотров из браузера — проверить

**Наблюдение на фронтенде.** `sendViewBeacon` вызывается в браузере и строит URL из `DOCUMENTS_API_URL`. Это серверная переменная (без префикса `NEXT_PUBLIC_`), в клиентском бандле её нет: `documentsApiBaseUrl()` бросает исключение, а оно молча глотается. Значит, просмотры, скорее всего, **не засчитываются**, и `viewsCount` растёт только из других источников.

**Что нужно решить вместе с бэкендом (один из вариантов).**
- (а) Публичный URL эндпоинта просмотров + CORS для домена сайта; фронтенд получает его через `NEXT_PUBLIC_DOCUMENTS_API_URL`.
- (б) Фронтенд проксирует запрос через свой route handler (`/api/catalog/views/{id}`), бэкенд принимает запросы только от сервера сайта.

**Требования к эндпоинту в любом варианте.** Анти-накрутка (дедупликация по IP/сессии за окно, например 30 мин), ответ `204`, без авторизации.

## API-4 (P2). Экспорт в PDF / печать

**Что нужно.**
- Для публичного документа — готовый PDF в CDN, генерируется вместе с превью (API-1), поле `meta.pdfS3Key: string | null`.
- Либо `GET /catalog/documents/{id}/pdf` → `302` на подписанный URL.

**Фронтенд после релиза:** кнопка «Скачать PDF» в правой колонке, шаг 3 «Как использовать» ведёт на неё.

## API-5 (P2). Поиск и счётчики для страницы каталога

Нужны для функций из макета страницы каталога (поиск, счётчики на чипах, «Найдено: N»).

- Параметр `q` в `GET /catalog/documents`: поиск по `title`, `titleI18n`, `description`, `descriptionI18n`, `tags`; минимум 2 символа; без учёта регистра; морфология хотя бы для ru/en; сортировка по релевантности, когда `q` задан и `sort` не указан.
- В ответе списка: `total: number` — число документов под текущие фильтры.
- `facets` (по запросу `?facets=category,language`): `{ category: { [slug]: number }, language: { [code]: number } }`, посчитанные **без учёта собственного фильтра** (чтобы на чипах категорий было видно, сколько документов в других категориях).
- `GET /catalog/tags?limit=20&language=ru` → `[{ tag, count }]` по убыванию — для блока «Часто ищут» и автодополнения тегов.
- Задокументировать семантику `tags=a,b`: И (документ содержит все) или ИЛИ. Фронтенд предполагает **И**.

## API-6 (P3). Похожие документы

- `GET /catalog/documents/{id}/related?limit=6` — ранжирование по общим тегам, затем по категории, без самого документа.
- До его появления фронтенд добирает похожие сам: категория + первый тег (см. план страницы документа, `pickRelated`).

---

## Общие требования

- Все новые поля — **опциональные и обратно совместимые**; фронтенд обязан работать со старым ответом.
- Изменения контракта — в OpenAPI/документации сервиса, с примером ответа.
- Ошибки — `4xx/5xx` без тела-HTML; фронтенд деградирует до пустого результата и не ломает страницу.
